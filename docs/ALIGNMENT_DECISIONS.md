# Kanaka 产品对齐决策

> 用途：记录开发前需要共同确认的关键产品决策，避免设计、内容和工程在实现阶段产生不同理解。
> 状态：持续更新。

## 使用规则

每个对齐点使用以下状态：

- **待讨论**：尚未形成推荐方案。
- **讨论中**：已有方向，但仍有关键问题未确认。
- **已对齐**：可以作为后续设计和实现依据。
- **需验证**：已有假设，需要通过原型或用户测试确认。
- **已变更**：原决定被新决定替代，并保留变更原因。

已对齐不代表所有像素级细节都被冻结。影响产品身份、内容生产或技术架构的变更，需要回到本文档更新决定和影响范围。

## A-001：作品外层展示系统的视觉风格

- **状态：已对齐**
- **日期：2026-09-01**
- **影响范围：品牌、UI、场景、美术、动画、音频、无障碍、App Store 素材**

### 决策

Kanaka 不采用完整像素复古风作为 App 外层展示系统。

整体风格采用：

> **灾后博物馆修复 × 高级档案系统 × 安静手工作坊**

具体分层：

- **场景层**：半写实、安静的博物馆修复室。
- **UI 层**：现代档案与编辑设计，强调清晰、可信和高级感。
- **玩法层**：精确、安静的 Nonogram 网格。
- **奖励层**：彩色拼豆蓝图和制作资料。

核心原则：

> **像素是被修复的内容，不是操作系统本身。**

### 为什么不使用全像素 UI

- 作品和拼豆蓝图本身已经包含大量方格与色块，全像素外壳会与内容争夺注意力。
- 像素字体不适合承担大量中文、线索和材料信息。
- 容易产生复古街机或廉价手游感，与文明修复的高级、克制气质冲突。
- 不同设备分辨率和动态字体会放大像素边框与图标的缩放问题。
- 拼豆蓝图应该是视觉奖励，不应该淹没在同样像素化的界面里。

### 两条路径如何保持统一

“修复室”和“拼豆工坊”属于同一个 App、同一座档案馆和同一个视觉系统。

共同使用：

- 字体体系。
- 图标语言。
- 按钮、卡片和标签规则。
- 旧纸、黄铜、深色工作台和档案编号等视觉母题。
- 作品卡、蓝图卡和状态标记。
- 声音、触觉和转场语言。

允许存在的差异：

- **修复室**更暗、更有空间与电影感，使用深灰、深蓝、旧木和局部修复灯暖光。
- **拼豆工坊**更明亮、更精确，使用暖白工作台、色卡、材料盒和清晰的数据排版。

它们不是两个模式皮肤，而是同一间修复室里的“修复工作台”和“蓝图柜/拼豆工作台”。

### 像素元素的使用边界

适合使用：

- Nonogram 棋盘。
- 拼豆蓝图。
- 扫描网格。
- Fragment 修复进度。
- 从二值格子过渡到彩色作品的完成动画。
- 少量状态方块或档案编码装饰。

不使用：

- 像素主字体。
- 全局像素按钮和锯齿卡片。
- 像素化购买页与设置页。
- 8-bit 街机音效作为主要声音语言。
- 持续铺满背景的像素或故障效果。

### 棋盘原则

进入谜题后主动降低视觉噪音：

- 棋盘和线索拥有最高对比度。
- 背景纹理极轻，不使用持续动态背景。
- 每五格主分隔清楚。
- Filled、Excluded、Unknown 不只依赖颜色区分。
- 修复主题仅保留在边缘、工具和完成反馈中。

### 字体与排版方向

- 普通 UI、按钮和正文采用高可读性的系统无衬线字体。
- 作品名和章节标题可以使用经过授权、支持目标语言的衬线展示字体。
- 行列 clues 使用数字宽度稳定的字体。
- 档案编号可以使用等宽字体。
- 像素字体只能作为极少量装饰，不承载重要信息。

### 动效与声音方向

- 扫描光、网格聚焦、颜料恢复、纸张和抽屉移动。
- 不把跳帧像素动画或 glitch 作为主要动效。
- 谜题页声音短、柔和，不使用持续警报。
- Reduce Motion 下使用淡入或即时替换。

### 需要通过原型验证的部分

以下细节尚未冻结，应通过三个高保真关键屏幕验证：

1. 修复室主界面。
2. Nonogram 棋盘。
3. 拼豆工坊蓝图详情。

验收问题：

- 三个页面是否一眼看出属于同一个 App？
- 修复室是否有氛围但不恐怖？
- 棋盘是否足够安静、清楚？
- 工坊是否像专业制作工具而不是普通商城？
- 同一作品从受损、解谜、恢复到蓝图是否连续？
- 关闭动画、颜色或声音辅助后是否仍可完成主要任务？

## A-002：故事先行，学徒成长与专业画师双路径平等

- **状态：已对齐**
- **日期：2026-09-01**
- **影响范围：开场、首次体验、首页信息架构、角色文案、App Store 表达、教程和权益展示**

### 决策

Kanaka 的首次体验顺序固定为：

1. 先建立“长夜”、文明修复署和保存图像的故事背景。
2. 再向用户平等展示两条路径。
3. 用户选择初始路径，但选择不形成永久职业或功能锁定。
4. 进入主空间后，可以随时在两条路径之间切换。

两条路径不是“主玩法和附属工具”，也不是“免费玩法和付费捷径”，而是同一个文明保存目标下的两种工作方式。

### 路径 A：学徒成长

角色定位：**见习修复师**。

- 从基础扫描和小尺寸 Nonogram 开始。
- 学习行列线索、损毁类型和修复工具。
- 通过完成 fragment 推进章节与作品修复。
- 从见习逐步成长，获得修复评级、档案记录和亲手修复印章。
- 完成作品后获得对应拼豆蓝图。

核心体验是：

> 从不会修复，到能够独立恢复失落作品。

### 路径 B：专业画师

角色定位：**专业画师**。

- 从拼豆工坊、作品目录和蓝图制作能力开始。
- 关注作品效果、色号、数量、尺寸、底板和导出文件。
- 使用已经获得或拥有权益的蓝图进行专业制作。
- 可以直接进入任何已开放的修复关卡，理解作品来源并获得亲手修复记录。
- 不因选择专业画师而自动完成谜题或故事。

核心体验是：

> 以专业制作能力进入档案馆，把被保存的图像真正做成可以带回现实的作品。

“专业”描述的是用户的使用目标和工具深度，不代表拥有全部付费内容，也不代表跳过修复进度。具体蓝图如何获得由 A-003 和 A-004 决定。

### 平等规则

- 两条路径在角色价值、首页层级和产品宣传中平等。
- 两条路径共享同一作品库、蓝图库、购买状态和档案空间。
- 选择只决定首次落点与教学内容。
- 学徒可以随时进入工坊查看和制作蓝图。
- 专业画师可以随时进入修复室解谜和推进故事。
- 不要求创建两个角色档案，不重复保存作品和权益。
- 切换路径不清空或重置任何进度。

### 首次体验

```text
开场故事：长夜与文明修复署
→ 共同任务：保存人类曾经看见过的图像
→ 平等路径选择
   ├─ 学徒成长：进入 5×5 修复教学
   └─ 专业画师：进入工坊与蓝图工具教学
→ 回到共同修复室
→ 两条路径随时切换
```

故事背景必须先于路径选择，否则用户无法理解为什么解谜和拼豆工坊会出现在同一个 App 中。开场保持短、可跳过；已经看过的用户不重复强制播放。

### 品牌与 App Store 表达

品牌核心不单独偏向某条路径，而是先表达：

> 在长夜之后保存文明图像。

随后平等展示两种参与方式：

- 通过逻辑修复作品，经历学徒成长。
- 以专业画师身份使用蓝图完成真实制作。

App Store 的前几张截图应覆盖共同故事、学徒修复和专业工坊，避免让任一类用户误以为另一条路径只是隐藏功能。

### 尚需通过原型验证

- 路径名称是否直接使用“学徒成长 / 专业画师”，还是采用更世界观化的名称。
- 专业画师首次教学是否需要提供一份免费完整蓝图样本。
- 用户完成任一路径教学后，如何最自然地发现另一条路径。
- 路径选择页面是否需要说明“之后可以随时切换”。
